# dep-graph

Инструмент визуализации графа зависимостей пакетов npm.
Практическая работа №2, дисциплина «Конфигурационное управление»,
вариант 16. Язык реализации: Python 3.10+, сторонние библиотеки не нужны.

## 1. Общее описание

Программа запускается из командной строки. Все настройки задаются
опциями командной строки. Зависимости пакета берутся из репозитория
npm по URL (по умолчанию `https://registry.npmjs.org`). Для этого
используется только стандартная библиотека Python (`urllib`), готовые
менеджеры пакетов не применяются.

Сейчас (этап 3) программа строит **граф зависимостей с учётом
транзитивности** и выводит его на экран по строке на пакет:
`пакет -> его зависимости`.

### Как устроен сбор данных

Модуль `src/npm_client.py`:

- `build_url(repo, name)` — строит адрес `<repo>/<имя>/latest`
  (в именах вида `@scope/name` символ `/` кодируется как `%2F`);
- `fetch_manifest(repo, name)` — скачивает JSON с описанием
  последней версии пакета и превращает сетевые ошибки в `RepoError`;
- `extract_dependencies(manifest)` — берёт из JSON поле
  `dependencies` и возвращает отсортированный список имён;
- `NpmRepository(url).get_dependencies(name)` — всё вместе.

Учитываются только зависимости из поля `dependencies` последней
версии пакета.

### Построение графа

Модуль `src/graph.py`, функция `build_graph(root, get_neighbors,
max_depth, substring)`:

- обход **в ширину (BFS) с рекурсией**: рекурсивная функция
  `visit_level` обрабатывает один уровень графа и вызывает сама себя
  для следующего;
- **глубина**: `max_depth=1` — сам пакет и его прямые зависимости,
  `2` — ещё и их зависимости и т. д.;
- **фильтр**: пакеты, в имени которых есть подстрока, не учитываются
  (вместе с их ветками);
- **циклы**: каждый пакет разбирается один раз, поэтому цикл не
  приводит к бесконечной рекурсии; ребро цикла (например, `C -> A`)
  в граф попадает.

### Тестовый репозиторий

Опция `--test-mode` включает чтение графа из файла
(`src/file_repository.py`). Формат: одна строка на пакет, имена —
большие латинские буквы, `#` — комментарий.

```
A: B C
B: C
C:
```

Готовые примеры лежат в `tests/data/`: `simple.txt` (ромб),
`cycle.txt` (цикл и самозависимость), `chain.txt` (длинная цепочка),
`demo.txt` (ромб, цикл и обход вместе).

## 2. Описание настроек

| Опция | Описание | По умолчанию |
|-------|----------|--------------|
| `-p`, `--package` | Имя анализируемого пакета (обязательно) | — |
| `-r`, `--repo` | URL репозитория npm или путь к файлу тестового репозитория | `https://registry.npmjs.org` |
| `-t`, `--test-mode` | Режим работы с тестовым репозиторием (`--repo` — файл) | выключен |
| `-a`, `--ascii-tree` | Вывод зависимостей в виде ASCII-дерева | выключен |
| `-d`, `--max-depth` | Максимальная глубина анализа (1–100) | `2` |
| `-f`, `--filter` | Не учитывать пакеты, в имени которых есть подстрока | пусто |

Обработка ошибок: программа печатает понятное сообщение
`Ошибка: ...` и завершается с кодом 1, если:

- не указано имя пакета или оно некорректно (в тестовом режиме имя
  состоит только из больших латинских букв);
- URL репозитория некорректен (нужен `http://` или `https://`);
- в тестовом режиме файл не указан или не найден;
- глубина не является целым числом от 1 до 100;
- имя анализируемого пакета содержит подстроку фильтра.

Ошибки получения данных (пакет не найден, репозиторий недоступен,
ответ не JSON) тоже выводятся как `Ошибка: ...` с кодом 1.

## 3. Сборка и запуск тестов

Сборка не нужна. Запуск тестов:

```
python3 -m unittest discover -s tests -t . -v
```

или `make test`. Проверка стиля: `make lint` (нужен `flake8`).

## 4. Примеры использования

Граф ромба `tests/data/simple.txt` (A зависит от B и C, оба зависят от D):

```
$ python3 -m src.main -p A -t -r tests/data/simple.txt -d 3
Граф зависимостей пакета A (глубина 3, фильтр ''):
  A -> B, C
  B -> D
  C -> D
  D -> (нет)
Пакетов: 4, зависимостей (рёбер): 4
```

Ограничение глубины (`-d 1`) — только прямые зависимости:

```
$ python3 -m src.main -p A -t -r tests/data/simple.txt -d 1
Граф зависимостей пакета A (глубина 1, фильтр ''):
  A -> B, C
  B -> (нет)
  C -> (нет)
Пакетов: 3, зависимостей (рёбер): 2
```

Фильтр (`-f C`) — пакет C и всё, что идёт через него, пропускается:

```
$ python3 -m src.main -p A -t -r tests/data/simple.txt -d 3 -f C
Граф зависимостей пакета A (глубина 3, фильтр 'C'):
  A -> B
  B -> D
  D -> (нет)
Пакетов: 3, зависимостей (рёбер): 2
```

Циклические зависимости (`tests/data/cycle.txt`):

```
$ python3 -m src.main -p A -t -r tests/data/cycle.txt -d 10
Граф зависимостей пакета A (глубина 10, фильтр ''):
  A -> B, D
  B -> C
  D -> D
  C -> A
Пакетов: 4, зависимостей (рёбер): 5
```

Цепочка с ограничением глубины (`tests/data/chain.txt`, `-d 2`):

```
  A -> B
  B -> C
  C -> (нет)
```

Реальный репозиторий npm:

```
python3 -m src.main -p debug -d 5
python3 -m src.main -p express -d 2 -f http
```

Неизвестный пакет тестового репозитория:

```
$ python3 -m src.main -p X -t -r tests/data/simple.txt
Ошибка: пакет не найден в тестовом репозитории: X
```
